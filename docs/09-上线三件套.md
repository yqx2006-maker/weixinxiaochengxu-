# 9. 上线三件套：类目、隐私声明、域名

> 这三样在开发期**完全不挡路**，全在提审那一刻一次性算总账。三样配好，审核能少走好几轮弯路。

## 9.1 服务类目：你申报的"身份"

**去哪**：mp 后台 → 设置 → 基本设置 → 服务类目。

一条原则：**类目必须盖住你的核心功能**。审核员会拿类目对着功能核，"工具"类目的小程序里做了用户发帖，功能本身再干净也会因类目不符被驳回。

个人主体先记两条硬限制（都在我们项目里真实撞过）：

- **AI 生成内容（"深度合成"类目）个人主体不可选**。判定标准是"内容是否由 AI 实时生成"——我们曾试图把界面上所有"AI"字样删掉来规避，**没用**：审核看功能实质，不看文案；
- **用户发内容（UGC）属"社交"范畴，个人主体未开放**。帖子、评论都算。

（大白话：类目就是营业执照上的经营范围。卖早饭的执照开不了网吧——不是网吧违法，是执照对不上。想清楚了再选，选错=重提一轮。）

## 9.2 隐私声明：用什么写什么

**去哪**：mp 后台 → 设置 → 服务内容声明 → 用户隐私保护指引。

三条填法纪律：

1. **用了才声明，声明了就必须真在用**。多写一项，审核就多问一句"哪里用了"——答不上来反而扣分；
2. **写清方向和边界**。我们项目里剪切板只有 3 处**写入**（复制配文）、0 处**读取**，而声明对读写都算——必须声明，写法是"用于把生成的配文写入剪切板，**不读取剪切板中的其他内容**"。后半句是防审核误以为你在偷读用户剪贴板；
3. **存储期限不用勾固定年限**，用平台默认的"最短必要时间"承诺。

声明前做一件事：全项目搜一遍实际调用的接口（`chooseMedia`、`saveImageToPhotosAlbum`、`setClipboardData`……），**以代码为准，不以记忆为准**。我们自己就曾漏判过剪切板（以为可以不声明，复查代码发现写入也算）。

（大白话：隐私声明不是保证书写得越多越诚恳。每一行都是审核员会追问的考题——只答会做的题。）

## 9.3 服务器域名：给小程序报备"能访问谁"

**去哪**：mp 后台 → 开发管理 → 开发设置 → 服务器域名。

规则：小程序正式环境只能请求**报备过的**域名，要求 **HTTPS + ICP 备案**。

- 用云开发的注意：云函数走 `wx.cloud.callFunction`，**不占**这个域名名单——这是选云开发的又一好处；
- 自己的后端接口（如果有）必须加进 request 合法域名；
- 开发期可以在工具的本地设置里关掉"校验合法域名"图省事——**这是开发期特权，上线前必须把域名配齐**，真机可不吃这套。

（大白话：域名白名单就是"访客名单"。开发时你能带人走侧门，正式开业后没名单的一律进不来。）

## 9.4 提审前自检清单

这张单子提审前过一遍，都是我们真实漏过或差点漏的：

- [ ] 类目覆盖核心功能（对着功能列表核一遍）
- [ ] 隐私声明与代码实际调用一致（全项目搜接口）
- [ ] 域名都配好（或确认没用自己的后端）
- [ ] 小程序名称、头像、简介填好且一致
- [ ] **真机把主路径完整走一遍**（生成 → 打卡 → 出片 → 保存）
- [ ] 造好演示数据：有进行中的路线、有几条打卡、奖章墙点了几个、出片页有成片——空壳给审核员看，观感直接垮
- [ ] 图片总体积达标（第 8 节的教训）
- [ ] **要给谁体验，先把对方微信号加进体验成员**——给评委演示前发现"扫码无权限"，是最尴尬的一种翻车

（大白话：审核员和第一批用户看到的，是你"故意让他们看到的样子"。清单的作用就是让"故意"真的成立。）
