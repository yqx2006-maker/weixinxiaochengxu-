# 11. 坑清单：前面没讲过的，全在这里

> 第 1~10 节已经顺手讲掉的坑（分享驳回、地图假路线、换照片丢失、AI 输出容错、体积超标……）不再重复。这一节只收**剩下没讲过的 18 条**，每条四段：现象 → 原因 → 修法 → 一句话。

## A. 云开发（4 条）

**A1. 云函数默认超时 20 秒，图像生成必挂**
现象：本地测试通过，部署后图像生成必然失败。原因：图生图一次 20~60 秒，云函数默认只给 20 秒。修法：函数目录下加 `config.json` 写 `"timeout": 300`，同时在界面写明"最长约 X 秒"。

**A2. 云函数之间不能共享模块**
现象：两个云函数要用同一份限流逻辑，`require` 不到。原因：每个云函数是独立部署单元，跨目录引用不存在。修法：同源复制两份，并在文件头写明"两边必须同步改"。

**A3. 坐标批量回填超时且静默失败**
现象：部分路线的站点永远"没有坐标"，点导航弹"暂未收录"。原因：坐标在生成路线时一次性批量查 8 个，超时后静默跳过，那条路线永久缺坐标。修法：改成**按需现场补查**——用户点导航时查单个（约 2 秒），成功后写回数据，下次秒开。

**A4. 告警群建不成，自定义告警就发不出去**
现象：控制台配自定义告警时建群报错，规则配了却没人收到。原因：自定义告警只支持"群告警"一种渠道。修法：改用基础告警——它支持公众号 + 群两种渠道，公众号那条不依赖群。

## B. 后台与权限（3 条）

**B1. 管理员入口死循环：首次部署永远进不去**
现象：内容审核后台需要"管理员"身份才能看到入口，而成为管理员又必须先进后台页输口令——首次部署时谁都不是管理员 → 入口永远不出现。修法：入口条件改成 `是管理员 或 还没有管理员`（没有管理员时显示"认领入口"）；`hasAdmin` 初始值必须是 true（安全态），避免首屏闪出认领框。
（大白话：先有鸡还是先有蛋的问题——答案是"没蛋的时候先把鸡的门打开"。）

**B2. 云端一抖动，后台入口对所有用户外露**
现象：云端请求偶尔失败时，所有用户都看到"认领管理员"入口。原因：前端把"查询失败"当成了"没有管理员"（hasAdmin 被写成 false）。修法：拿不到结果就保持原状态，不写 false；服务端每次请求都二次鉴权，前端显示只是 UI 便利。
（大白话：查不到 ≠ 没有。保险丝的方向装反，一停电全楼门大开。）

**B3. 管理员口令的时效性**
现象：口令写在源码里，注释标着"提交前必须更换"。实际它自动失效了——因为认领接口只在"还没有管理员"时放行，认领一次后口令永久作废。但这是**巧合不是设计**：正确做法是口令从环境变量读，或首次部署时显式设置。

## C. 数据与状态（6 条）

**C1. 真机和开发者工具的存储互不相通**
现象：同一个功能工具里正常、真机上不对。原因之一：两边的本地存储是两套独立数据。你在工具里造的测试数据，真机上一个都没有。
（大白话：模拟器和手机是两个平行宇宙。排查真机问题前，先在真机上把数据造一遍。）

**C2. 默认档案被就地污染**
现象：清空存储后，新用户带着旧积分和旧奖章。原因：默认档案是个全局常量对象，加分、计数都是"取出来就地改再放回去"——默认值本身被改脏了。修法：改成工厂函数，每次要默认档案就造一个全新的。
（大白话：展示样品被顾客直接穿走了。样品要么锁起来，要么每次拿新的。这个 bug 是写测试时被测试自己抓出来的。）

**C3. 打卡统计重复计数**
现象：给已完成的站点重复打卡，统计数据蹭蹭涨。原因：每次打卡都无条件累加。修法：用调用**之前**的状态判断——已完成的只换图不计数。

**C4. 从历史"继续"会清空进行中的进度**
现象：从"历史路线"点继续，正在走的那条路线进度全丢。原因：直接覆盖了活动路线，没先把旧的归档。修法：接管前先归档当前路线。
（大白话：换床睡之前，先看床上有没有人——有人的先安顿好。）

**C5. 两个去重坑：id 撞号 + 路线重复计数**
现象一：并发补全时不同路线的数据互相覆盖（AI 生成路线的 id 是 `ai_0`、`ai_1` 这种批次内序号，跨路线必然撞号）。修法：去重 key 用 `id + 名称`。现象二：奖章"生成 N 条路线"提前解锁。原因：统计时历史路线和进行中路线没去重，走完的路线在两边各算一次。修法：先按 id 去重再统计。

**C6. 缺字段直接崩页面**
现象：云端某个帖子里没有"建议"字段，点"加入路线"整页报错。原因：代码里 `data.tips[0]` 直接取值，没兜底。修法：所有来自云端/用户输入的字段，取值前先给默认值。
（大白话：别人的数据不可信，包括你自己的云端。伸手拿之前先问一句"有吗"。）

## D. 画布与图像（5 条）

**D1. 复用查询对象 → 画布全白**
现象：页面上多个画布，合成出来全是空白。原因：多个画布复用了同一个查询对象，第二次 `exec` 拿不到节点。修法：**每个画布独立创建查询对象**，并在代码里写明原因——不写，这段"看起来能合并"的代码一定会在某次重构中被合并回去。

**D2. 画字之前没设字体 → 字号继承残留值**
现象：某一种排版的大标题明显偏小，其他都正常。原因：`fillText` 前没设置 `ctx.font`，字号用了上一次画图剩下的值。修法：canvas 是隐式状态机——**每次绘制前显式设置字体、颜色、对齐**，别依赖"上一步设过了"。
（大白话：画布记性很好但很瞎，你不明说它就用上一次的。）

**D3. PNG 调色板模式转 RGB 丢色**
现象：PNG 转 JPG 后底色出黑块。原因：导出的图是索引色（P 模式），直接转 RGB 会把色号当灰度。修法：先转 RGBA、把透明区域压成白底、再转 RGB。

**D4. AI 生成图带水印**
现象：生成的封面图右下角有"AI 生成"水印。修法：**先裁掉底部约 11%，再缩放**——顺序反了水印位置跟着变，裁不准。

**D5. 文件写入间歇性失败**
现象：批量写图片文件，同一批有的成功有的失败。修法：先写临时文件，再用"移动"替换目标——失败不留半成品，还能重试。

**D6. 本地临时路径会失效**
现象：用户重开小程序后，之前的图全裂了。原因：临时文件路径重启后可能失效。修法：要长期保留的引导用户"存入相册"；界面预览的，加载失败自动降级为空位（别显示破图）。
（大白话：临时工不能签长期合同。要留的东西当天就转正——存进相册。）

## E. 工程与工具链（5 条）

**E1. shell 写文件时反引号被吞**
现象：用命令行的 heredoc 写 Markdown，正文里的代码标记被静默删掉，文档损坏。原因：不加引号的 heredoc 会让 shell 执行内容里的反引号。修法：heredoc 一律加引号；或者根本不用命令行写长文——用文件写入工具。

**E2. git 全局镜像重写 → 推送时凭据发给第三方**
现象：推送 GitHub 实际发到了一个镜像站。原因：全局配置里有"把 github.com 重写到镜像"的规则，**推送时凭据跟着发过去**。修法：推送前 `git config --get-regexp 'url\..*insteadof'` 查一遍；有重写就用干净配置文件（`GIT_CONFIG_GLOBAL` 指向）执行推送。
（大白话：你寄快递的地址被全局改写过——寄件前看一眼最终地址，别把密码写在中转站。）

**E3. 中文路径下编辑器"报成功实际没写入"**
现象：批量编辑 12 处只落了 2 处，工具却显示成功。修法：改用整文件重写；重写后**用搜索工具复核关键内容**。
（大白话：中文路径下"成功"不一定是真成功。复核一次 30 秒，丢内容找一次一下午。）

**E4. 无头浏览器打印 PDF 的三个坑**
① 同一个配置目录被上次进程占用 → 换个目录就成功；② 返回非零退出码但文件其实已写出 → **判断成功看文件修改时间**，别看退出码；③ 截图模式下页面边距不生效 → 验证 PDF 要看页面尺寸，别靠截图目测。
（大白话：自动化工具的"报错"和"成功"都不可全信，最终以产物为准。）

**E5. 批量删除误伤**
现象：整个工具目录从工作区消失（41 个文件）。起因疑似批量删除与批量添加的时序问题。这次零损失的唯一原因：**全部已提交**，一条恢复命令全回来。纪律：删之前确认工作区干净；优先靠版本控制恢复而不是"小心点删"；改前备份进版本控制，别放工作区。
（大白话：删东西的安全感不该来自手稳，该来自"反正都提交过了"。）
