# 8. 调试：我不会写代码，是这样把 bug 修完的

> 全程我不会写代码、看不太懂代码。这一节讲调试的四个面板怎么用、真机上翻过哪些车、以及**不会写代码的人怎么把 bug 交给 AI 修**。

## 8.1 四个面板：按"你怀疑什么"选

调试器在工具下半屏，四个标签覆盖九成问题：

| 你怀疑什么 | 打开哪个 | 看什么 | 我们的真实例子 |
|---|---|---|---|
| 报错/白屏 | **Console** | 红字，**第一行就是病根**，点行号跳代码 | 生成失败时弹窗里那句"云服务繁忙"，就是从 Console 的报错里认出是触发限流（429），才没去瞎改代码 |
| 该显示的没显示 | **AppData** | 当前页面手里到底有没有数据 | 出片灵感的"随意版/专业版"显示成同一句话，AppData 里一看：两版字段存了同一个值——数据问题，不是样式问题 |
| 网络请求不对 | **Network** | 请求发了没、状态码、返回内容 | 机位坐标批量查询超时，就是在这里看到请求拖了 8 秒后失败 |
| 存的数据不对 | **Storage** | 本地存储的键值，可以手动清 | 清空存储后新用户带着旧积分，就是在这里看到默认档案被污染的痕迹 |

## 8.2 真机问题实录：模拟器说没用的那部分

以下问题**全部只在真机出现**，模拟器里一切正常：

| 现象 | 真相 |
|---|---|
| 地图上相邻两点画出 103 公里的连线 | AI 挂了降级到通用模板后，"老城街区"这类没有真实位置的站名被拿去查坐标，查到同名小区甚至外省——只有真机上那条真实降级的路线才暴露 |
| 生成完跳到了任务清单，"没有总的路线" | 跳转写的是直达任务页，跳过了唯一的总览视图；工具里我一直点的都是开发专用入口，看不出来 |
| 打卡后点"换一张"，新照片无声消失 | 确认按钮只在"未打卡"分支渲染，已打卡分支点了个寂寞——真机用户实际操作的路径，和我在工具里测的不是同一条 |
| 反复生成提示"云服务繁忙" | 真机上连续测试把限流触发了；模拟器里没这个频率 |

**结论就一句：每个版本发布前，真机把主路径完整走一遍。** 你在工具里测的和用户用的，经常不是同一条路。

## 8.3 怎么把 bug 交给 AI 修（不会写代码版）

不会写代码不影响修 bug，但**描述问题的能力决定修复速度**。我的固定格式：

```
1. 我在哪一步：页面 A → 点了按钮 B
2. 期望：应该出现 X
3. 实际：出现的是 Y
4. Console 红字第一行（原样复制/截图）
5. 谁能复现：每次都出 / 偶尔 / 只有真机
```

几个实战要点：

- **报错原样给，不要转述**。"报错了"没有信息量，红字第一行有；
- **弹窗里带上原始错误信息**是我在设计时就让 AI 加的——后来每次排障，第二行那句原因都是最准的线索；
- **修完让 AI 汇报"改了哪几个文件、为什么这么改"**。不用看懂全部，但你能在下次同类问题时说清"上次也是这样修的"，而且能发现"它是不是改多了"；
- **修完真机复验一遍**，别只看 AI 说"已修复"。

（大白话：你和 AI 修 bug 的关系像病人和医生——你负责把症状说准，不需要会开刀。症状说准了，AI 的诊断比想象中准得多。）

## 8.4 提审前的体积与一致性检查

两样东西不会报错，但会让你在提交环节卡住：

**图片体积**：代码质量扫描对图片资源有体积要求，而且卡的是**全部图片加起来的总体积**，不是单张。我们最初十几张图 195KB 压线通过，换成高清版直接涨到 990KB 被拒——后来两段压缩（先降质量、再降分辨率）收到 165KB。**换任何资源前先算总账**。

**绑定一致性**：wxml 里绑的事件名，脚本里必须真有这个函数。绑错了**不报错，只是按钮点了没反应**。我们有一个静态校验脚本专门查这个（删函数忘删绑定的高发问题），重建后会放进 `templates/`。
