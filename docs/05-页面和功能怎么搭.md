# 5. 页面和功能怎么搭

> 这一节讲"东西是怎么长出来的"：先搭骨架，再把页面一个个生出来，最后回头打磨。全部过程是我在 AI 工具上提需求、AI 写代码、我验收。

## 5.1 先搭骨架：一排 Tab 定江山

开发第一天的第一件事，不是写任何功能，是把**底下那排 Tab（导航栏）和空页面**搭出来。

为什么这是第一步：**骨架定了，每个功能都有归属地**，后面不会出现"这个功能放哪个页面"的反复。我们的定法很土但有效：

1. 写一句话主路径："用户选城市选风格 → 生成路线 → 按任务一站站拍 → 拍完拼图保存"；
2. 把主路径切成几段，一段一个 Tab：**首页（选）→ 任务（走）→ 出片（拼）**；
3. 剩下的"看别人的"和"自己的"各一个 Tab：**发现、我的**。

五个 Tab 就这么定了，全程没动过。

## 5.2 多页面怎么组织不乱

页面一多（我们 14 个），三件事不搞清楚就会乱：

**① 每个页面是四个文件**：

| 文件 | 管什么 | 大白话 |
|---|---|---|
| `xxx.ts`（或 js） | 数据和逻辑 | 脑子 |
| `xxx.wxml` | 页面结构 | 骨架 |
| `xxx.wxss` | 样式 | 衣服 |
| `xxx.json` | 页面配置 | 证件 |

目录按 Tab 分文件夹，页面名即文件夹名，找东西靠猜都能猜中。

**② 数据分三层放**（和第 4 节的"三个在哪"呼应）：

- **页面临时的**（比如输入框当前内容）→ 页面自己的 `data`，走了就没；
- **要留下的**（路线、打卡记录、积分）→ 手机本地存储，一行代码读写；
- **要给大家看的**（用户发的帖子）→ 云开发数据库。

**③ 页面之间怎么传东西**：

- 简单的带个参数：跳转链接后面缀 `?id=xxx`，像网址一样；
- 复杂的（比如拍完一张照片要把图带回来）用"事件通道"——A 页面等 B 页面回来时递东西。

（大白话：参数是递纸条，事件通道是亲手交接。跨 Tab 跳转用"切 Tab"，普通页面用"推入新页"——这两种跳转手感不一样，别混。）

## 5.3 一个页面的诞生：拿"发帖带图"当例子

用一次真实的小需求，展示"我 + AI"是怎么长出一个功能的：

**第一步 · 我提需求（一句话）**："用户发帖现在没图，不像样。加上传一张封面图。"

**第二步 · AI 给方案**：它列出了要动的地方——数据结构加一个可选字段、发布页加一个选图按钮、列表卡片和详情页显示这张图。我确认没问题，它写。

**第三步 · 我验收**：在工具里发一条带图的帖子、发一条不带的，看列表和详情页对不对。**验收是在模拟器里点出来的，不是看代码**——我也看不懂。

**第四步 · 补边界**：没图的用户占多数，AI 给了兜底（没图时显示渐变色块），我确认观感可以。

整个过程我的产出：一句话需求 + 几轮"这里不对/可以了"。AI 的产出：四个文件的改动。**你不需要会写，但必须会点**——像产品经理验收一样把每个角落点一遍，你点不出来的问题，上线就是用户的了。

## 5.4 先跑通再打磨：同一个页面的三个版本

以出片成果页（拼封面和九宫格那页）为例，它先后长过三个样：

| 版本 | 状态 | 那一步的意义 |
|---|---|---|
| 第一版（开发第 2 天） | 能拼图，丑，偶尔白屏 | **把数据长什么样定了下来**——哪些字段、存哪、怎么取。这是后面一切的地基 |
| 第二版（重构） | 排版重做成"宣纸题签"风格 | 这时才知道用户真正在意什么，改版有靶子 |
| 第三版（细节修复） | 发现标题字号继承了残留值，显式设置后正常 | 磨到最后 5% 的观感问题 |
