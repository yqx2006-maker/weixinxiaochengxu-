# 06 · 从注册到上线：一条龙实操

这一篇讲**做一个微信小程序、从注册到用户能搜到的完整流程**。每一步都写清楚"去哪点、填什么、多久"。个别步骤用了我们项目里的真实经历做例子。

先给全景图，一共七步：

```
① 注册小程序（拿 AppID）→ ② 装工具开项目 → ③ 写代码调试
→ ④ 上传代码 → ⑤ 上线前准备（类目/隐私/域名）→ ⑥ 提交审核 → ⑦ 发布
```

（大白话：前面三步是"做"，后面四步是"审"。做的时候天高海阔，审的时候处处是规矩——所以 ⑤ 一定要在 ④ 之前想好，不然到 ⑥ 会白跑好几轮。）

---

## ① 注册小程序：拿到 AppID

**去哪**：微信公众平台 `mp.weixin.qq.com` → 立即注册 → 小程序。

**要准备**：一个没注册过公众号/小程序的邮箱、身份证、手机号。

**个人主体还是企业主体**（这个选择影响很大，先想清楚）：

| | 个人主体 | 企业主体 |
|---|---|---|
| 注册费用 | 免费 | 注册免费；微信认证 300 元/年（部分场景需要）|
| 能用的类目 | **少**：工具、旅游攻略、生活服务等 | 多：含电商、社交等 |
| 不能做的 | 支付、直播、社交（UGC 发布/分享）、**AI 生成内容（深度合成类目）** | 基本都能做，按资质 |
| 适合 | 作品、比赛、演示、个人工具 | 要收费、要用户发内容的 |

（大白话：个人主体免费够用，但你不能做"用户发帖"、不能做支付、不能做 AI 生成图这类内容。我们就是个人主体，社区功能和 AI 类目后来都是按这个约束设计的——详见第三册的权限合规篇。）

注册完成后，在 **设置 → 基本设置** 里能看到 **AppID**，一串 `wx` 开头的字母数字。

（大白话：AppID 就是小程序的身份证号。装工具、上传代码、后台配置，全靠它对号入座。）

## ② 装开发者工具、导入项目

**去哪**：微信官方文档 → 开发者工具下载页，选 **稳定版**（别选开发版/预发布版，除非要试新特性）。

**导入项目**：工具里「+」→ 导入 → 选项目根目录（必须有 `project.config.json`）→ 填 AppID → 起个名。

**工具界面四大块**（知道每块干嘛，就不慌了）：

| 区域 | 干嘛的 | 什么时候用 |
|---|---|---|
| **模拟器**（左） | 假装是一部手机，实时显示页面 | 每次改完代码自动刷新 |
| **编辑器**（中） | 写代码的 | 就是它 |
| **调试器**（下） | Console 报错 / Network 请求 / AppData 页面数据 / Storage 本地存储 | 排查问题时 |
| **工具栏**（上） | 编译 / 预览 / 真机调试 / 上传 | 见下文 |

几个按钮的区别，第一次容易懵：

- **编译** = 在模拟器里重新跑一遍（相当于刷新）；
- **预览** = 生成二维码，用**你自己**的微信扫，在真机上看（临时生效，下班就失效那种）；
- **真机调试** = 真机上跑，但电脑能看 log、能打断点（慢一些，查 bug 用）；
- **上传** = 把代码传到后台，用来做体验版或提审（见 ④）。

（大白话：编译是"自己看"，预览是"手机上看"，真机调试是"手机上看还能查病"，上传是"交作业"。）

## ③ 日常调试：四个最常用的排查手段

按"怀疑什么"来选工具：

| 你在怀疑什么 | 用哪个 | 怎么用 |
|---|---|---|
| 报错了/白屏 | **Console** | 看红字，第一行通常就是病根；点行号能跳到代码 |
| 页面上该显示的没显示 | **AppData** | 看当前页面的数据到底有没有值——九成"没显示"是数据是空的，不是样式错了 |
| 网络请求失败 | **Network** | 看请求的状态码和返回体；域名不在白名单会直接报错 |
| 存的东西丢了/不对 | **Storage** | 直接看本地存储的键值，能手动清 |

**真机上的 Console**：预览版默认看不到 log。两个办法：用"真机调试"（电脑上看）；或在手机上打开 vConsole（真机调试自带）。

> **一条血泪经验：模拟器说没问题的，真机不一定没问题。**
> 我们项目里至少四个 bug 只在真机出现：地图画出荒谬的路线、生成后跳错页面、打卡照片静默丢失、权限弹窗行为不一致。原因：模拟器不处理真实的权限弹窗、存储和云函数冷启动。
> （大白话：模拟器是理想世界，真机是现实。验收标准只有一个——真机走一遍。）

## ④ 上传代码与体验版

**上传**：工具右上角「上传」→ 填版本号（如 `0.1.0`）和备注（写了什么）。

**设为体验版**：登录 `mp.weixin.qq.com` → **版本管理 → 开发版本** → 找到刚上传的 → 「选为体验版」→ 生成体验版二维码。

**谁能用体验版**：只有**体验成员**能打开。在 **成员管理 → 体验成员** 里加对方的微信号。

（大白话：体验版就是"内测包"。想给谁试，先把人家微信号拉进体验成员名单，再发二维码。没拉名单的人扫码会提示无权限——给评委演示前，先检查名单！）

两个细节：

- 体验版二维码有有效期（会过期，重新生成即可）；
- **体验版不经过代码审核**，所以类目、隐私这些"上线才查"的问题在体验版阶段不阻塞——但别因此拖着不做（见 ⑤）。

## ⑤ 上线前准备：三样东西没配好，审核多半白跑

这三样都在 `mp.weixin.qq.com` 后台配。

### 5.1 服务类目

**去哪**：设置 → 基本设置 → 服务类目。

个人主体能选的类目有限（工具、旅游攻略等）。**选类目的原则：类目必须覆盖你的核心功能。**

（大白话：审核员会拿你的类目对功能。你选"工具"却做了"用户发帖聊天"，就算功能本身没问题，类目对不上也会被打回。）

我们踩过的具体坑，记在第三册权限合规篇里：AI 生成内容对应"深度合成"类目，**个人主体不可选**；UGC（用户发内容）属"社交"范畴，**个人主体未开放**。这两条直接影响产品设计，**最好在写代码之前就知道**。

### 5.2 用户隐私保护指引

**去哪**：设置 → 服务内容声明 → 用户隐私保护指引。

**填法就一条：用了什么就声明什么，没用的千万别多写。**

- 每条声明都会被审核问"为什么"——多写的每一项都是给自己挖坑；
- 写的时候把"方向"和"边界"说清楚。我们项目里剪切板只**写入**（复制配文）不读取，声明里就明确写"不读取剪切板中的其他内容"——这句是防审核误以为你在偷读用户剪贴板；
- 存储期限不用勾固定年限，用平台默认的"最短必要时间"承诺。

（大白话：隐私声明不是写得越多越安全。你多声明一个"位置信息"，审核就会问你"哪里用了定位"。没用就别写。）

### 5.3 服务器域名

**去哪**：开发管理 → 开发设置 → 服务器域名。

你的后端接口域名必须加进 **request 合法域名**，要求 **HTTPS + 备案**。用云开发的话，云函数走 `wx.cloud` 不占这个名单，但图片下载等其他域名要配。

（大白话：小程序只能访问"报备过的"网址。没报备的，模拟器里可能能通（关了校验），真机上必挂。）

## ⑥ 提交审核

**去哪**：版本管理 → 开发版本 → 「提交审核」。

要填的东西：

- **版本说明**：这次改了什么。写人话，比如"修复了保存图片失败的问题"。第一版就把主要功能列一遍；
- **其他材料**：部分类目要资质证明（个人主体的工具类目一般不需要）。

**审核要多久**：官方说法 7 天内，实际多数 1~2 天，快的几小时。赶上大促或节假日会慢。

**着急可以加急**：审核页有加急入口，每月有次数限制，按真实需求用。

**驳回之后怎么办**（重点）：

1. 看驳回理由。**有时它就一句话，没说哪个页面**——这时候先自己定位：全项目搜"分享""支付""定位""UGC"这些关键词，把可疑入口列出来；
2. 分清驳回的是哪类问题：功能类目不符？隐私声明没对齐？内容违规？——对策完全不同；
3. 改完重新提审即可，不用慌。

> **我们的真实经历**：第一次提审被驳回，理由只有一句——"设置的图片保存到手机相册，仅设置用户可以看，不属于社交，建议移除整改后，再去提交审核呢"。没说哪个页面。
> 我们当时把**全部 6 处分享入口**都删了，结果矫枉过正——后来才知道"转发小程序本身"（`onShareAppMessage`）是微信基础能力，**平台还会主动提示你定义它**，不用删；真正踩线的是"把用户生成的图片直接转发到聊天"这类内容分发。来回改了两轮才定稿。
> （大白话：驳回理由看不懂时，别一刀切全删。先分清"哪类能力"有问题，只动那一类。）

---

## ⑦ 发布

审核通过后，**不会自动上线**——要去 **版本管理 → 审核版本 → 「发布」** 手动点。

- 点了发布，全量用户几分钟到几小时内可见；
- 之后每次更新：改代码 → 上传新版本 → 提审 → 通过 → 发布，循环；
- 不想一次全量，可以用**分阶段发布**（按比例放量），个人项目一般用不上。

（大白话：审核通过只是"及格"，还得你自己点"发卷"。忘了点，用户那边永远看不到新版。）

## 附：常见驳回原因清单（踩坑高发区）

按我们遇到和看到的频率排：

| 高发原因 | 典型表现 | 怎么避免 |
|---|---|---|
| **类目与功能不符** | 选"工具"却做社区/电商/定位 | 提审前把功能列表和类目对一遍；个人主体先查"未开放类目"清单 |
| **隐私声明与实际不符** | 声明了没用到的权限 / 用了没声明的接口 | 用到的才声明；声明前全项目搜一遍 API 调用 |
| **诱导/强制分享** | "分享后解锁""不分享不能继续" | 别做任何"分享换功能"的设计 |
| **内容违规** | UGC 没有审核机制、涉政涉黄 | UGC 必须有举报 + 人工审核通道（我们做了内容审核后台） |
| **未取得资质** | 医疗、金融、直播类目无资质 | 个人主体直接绕开这些类目 |
| **功能不完整** | 点进去全是"建设中" | 别拿半成品提审，审核员真的会点 |

（大白话：审核员是拿"你的声明"对着"你的功能"逐项核对的。声明与功能对不齐，是最常见也最容易避免的驳回原因。）
