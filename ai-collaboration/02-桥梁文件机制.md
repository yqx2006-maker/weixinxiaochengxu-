# 02 · 桥梁文件机制

**一句话：用一份放在项目根目录的文件，承载两个 AI 之间的全部协调状态。**

（大白话：桥梁文件就是一个放在项目根目录的 Markdown——谁负责什么、谁在干什么、谁跟谁有分歧，全写在里面。AI 每次开工先读它、收工后写它，相当于大家共用的公告板。）

它的结构很简单，一共六节。但每一节都对应一个具体的失效模式。

---

## 文件的六节结构

```
一、铁律            ← 不可协商的规则，违反即视为"打架"
二、参与方          ← 谁在干、各自擅长什么
三、文件所有权表     ← 逐条列出路径归属
四、任务板          ← 当前在做什么、谁在做、什么状态
五、消息区          ← append-only 的通信记录
六、交接档案 / 变更记录 ← 阶段性成果与架构事实的快照
```

完整模板见 [`../templates/AI-COORDINATION.md`](../templates/AI-COORDINATION.md)。下面逐节讲为什么。

---

## 一、铁律：把最贵的错误写死

实际使用的六条（原文保留，因为措辞本身就是它起作用的原因）：

| # | 铁律 | 对应的失效模式 |
|---|---|---|
| 1 | **先看所有权，再动文件**：只有 owner 可以改，非 owner 绝不直接改 | 覆盖 |
| 2 | **认领制**：未分配的任务必须先留言认领（文件路径 + 改动范围 + 时间），对方无异议或人拍板后才动手 | 两人做同一件事 |
| 3 | **共享文件由一方独占**：另一方需要时走消息区提需求，由 owner 统一落笔后广播 | 配置文件半成品 |
| 4 | **收工必汇报**：改完追加一条 `[完成] 文件 + 一句话摘要 + 是否影响他人` | 重复实现（**这是发现重复实现的唯一手段**） |
| 5 | **冲突裁决权归人**：意见不一时各写一行理由，由人决定，**不偷偷改代码** | 双方互相覆盖 |
| 6 | **禁止互相回滚**：发现问题走消息区，由 owner 自己修 | 回退 |

### 为什么措辞要这么具体

**"先看所有权再动文件"** 比 **"注意不要冲突"** 有效得多——前者是一个**可执行的动作**（去查表），后者是一个**无法执行的态度**。

这和第 03 篇会发现的原则是同一条：**给动作，不给形容词。** 写技术文档、写产品文案、给 AI 下指令，用的是同一条纪律。

### 第 6 条为什么特别重要

"发现问题走消息区，由 owner 自己修"——这条看起来效率低（要等对方），但它防的是一个非常具体的灾难：

**A 发现 B 的代码有 bug，直接改了。** 而 B 此时正在本地重构同一个文件。B 下次提交时，A 的修复被覆盖——**bug 又回来了，而且没人知道它回来过**。

这在多人协作里叫"补丁丢失"，在 AI 协作里发生的概率极高，因为 AI 不会"顺手看到"别人的未提交改动。

---

## 二、参与方：写清"擅长什么"

不只是写名字，要写**各自负责的领域**。这决定了后面遇到新任务时谁该认领：

```
| 代号 | 身份 | 负责 |
|---|---|---|
| A | AI 助手（服务层） | 数据服务 / 云函数 / AI 链路 / 类型定义 / 文档材料 |
| B | AI 助手（界面层） | 页面结构 / 样式 / 视觉打磨 / 交互细节 |
| USER | 人 | 需求拍板 / 真机实测验证 / 冲突裁决 |
```

**注意人的角色**：人是**唯一的实测者与裁决者**。这条不能省——AI 无法在真机上验证，也无法在两种方案之间做价值判断。把这两件事明确划给人，能避免 AI 在这两件事上瞎猜。

---

## 三、所有权表：逐条列出

```
| 路径 | Owner | 说明 |
|---|---|---|
| `src/services/**` | A | 数据服务与 AI 链路 |
| `src/typings/**` | A | 类型定义 |
| `src/app.*` | A | 全局入口与配置 |
| 工程配置文件 | A | 编译与云配置 |
| `cloudfunctions/**` | A | 云函数 |
| `src/pages/**` 各页 `.ts` | A | 页面数据流与事件逻辑 |
| `src/pages/**` 各页 `.wxml` + `.wxss` | B | 结构与样式、视觉升级 |
| `本文件的消息区` | 双方 | 其余区块只读 |
| 全局文档 | A | 进度与提交材料 |
| 静态资源 | B | 图片资源（含体积约束） |
```

三条实操细节：

1. **末列写"说明"而不是"备注"**——说明这一列要写清**为什么归它**，减少后续争议；
2. **带约束的要带上**（如"单图保持 <200KB，超限会挂代码质量扫描"）——把工程约束挂在这里，比散落在文档里更容易被看到；
3. **本文件自己也要声明归属**："消息区双方可写，其余区块只读"。

## 四、任务板：让状态可查

```
| # | 任务 | 认领人 | 状态 | 备注 |
|---|---|---|---|---|
| T1 | 验证字段落到 UI | USER+A | ⏳ 待验证 | 实测由人做 |
| T2 | 图生图功能 | 拆两半 | ✅ 代码就绪 | 待部署后实测 |
| T3 | 提交材料 | A | ✅ 初稿完成 | 见某文档 |
```

**"拆两半"这三个字是任务板最有价值的能力**——它明确记录了"这个任务由两个人各负责一部分"。没有这一栏，就会出现两人都以为对方在做，或都以为自己做完了。

## 五、消息区：append-only 是核心设计

### 格式

```
[日期 · 代号] 类型(提案/认领/完成/提问/裁决请求)：内容
```

### 为什么只追加、不修改

**消息区是一份日志，不是一块白板。**

- **白板**：谁都可以擦掉重写。结果是——你看到的是当前状态，但看不到变化过程和原因；
- **日志**：只能追加。结果是——**任何时刻你都能回答"这个决定是什么时候、因为什么、由谁做的"**。

这对 AI 协作尤其关键，因为 AI 每次都是**冷启动**：它读这个文件时没有任何历史记忆。日志形态让它在 30 秒内建立起完整的上下文。

**实际效果**：项目进行到后期，这个文件积累了几十条消息，包含完整的决策链。任何一个新会话读完它，就知道"现在是什么状态、有哪些约定、哪些坑不能再踩"。

### 消息类型的实际用法

| 类型 | 用在什么时候 |
|---|---|
| **提案** | 提出方案或分工建议，等对方确认 |
| **确认 / 调整意见** | 对提案的回应。**允许提调整意见**，不要求无条件接受 |
| **完成** | 收工汇报（**唯一能发现重复实现的手段**） |
| **提问** | 需要对方提供信息（如"缺一个数据字段，请加"） |
| **裁决请求** | 双方意见不一，@人 决定 |

### 一段真实的消息（保留原文的语气）

> **[CBB] 撞车预警**：已确认 DSH 尚未广播出片页 `.ts` 骨架，而 CBB 在 USER 授权下已自主补齐 T2 全链路（含出片页 `.ts` 的字段与方法、服务层函数、云函数）。**若 DSH 正在搭 `.ts` 骨架，请先读 CBB 已落地的代码，在 CBB 基础上扩展而非重写，避免撞车。** 云函数归 DSH 所有，请复核参数契约并确认部署。CBB 待 DSH 复核结论，不擅自回滚。

这条消息里有四个值得学的动作：

1. **主动预警**——发现自己可能和别人撞车，先喊出来；
2. **给出具体文件与符号名**——不是"我改了点东西"，而是"请读 X 文件里的这几个方法"；
3. **区分所有权**——"我越界补了云函数，但那块归你，请复核"；
4. **明确下一步**——"待你复核，我不擅自回滚"。

**这三条纪律（主动预警、给出具体符号、明确下一步）让那次潜在的撞车变成了一次顺利的交接。**

## 六、交接档案：阶段性的"架构事实"

在文件末尾维护一份简短的架构事实清单，例如：

```
- AI 链路两条：文本（端内直连）+ 图生图（云函数中转，超时 300s）
- 出片页九宫格：用户自选 0~9 张，存本地键 `xxx`
- 保存兜底链：保存相册失败 → 预览（工具内右键另存 / 真机长按保存）
- 降级保命：文本失败→本地模板；图生图失败→原图预览
- ⚠️ 某些实现有历史原因，勿回退（附原因）
```

**这一节的作用是"防止后人好心办坏事"。**

比如"canvas 查询对象不能复用"这种事，看起来像是可以优化掉的冗余代码，实际是踩过坑之后的正确写法。**不写清原因，下一个读代码的人（或 AI）一定会把它"优化"回去。**

> **原则**：凡是"看起来多余但其实是必须有"的代码，都要在原地留注释说明原因。这是一条能省下大量返工的习惯。

## 最低可用版本

如果不想一次做全套，最小可用版本只需要三样：

```markdown
# AI 协作约定

## 所有权
- A 负责：<目录/文件列表>
- B 负责：<目录/文件列表>
- 共享文件（谁独占）：<列表>

## 铁律
1. 非 owner 绝不直接改；需要改动走消息区提需求
2. 收工必须追加一条 `[完成] 文件 + 摘要 + 是否影响他人`
3. 意见不一时不偷偷改代码，由人裁决

## 消息区（只追加）
[日期 · 代号] 类型：内容
```

**成本 5 分钟，收益在你第二次让 AI 改同一个文件时兑现。**

---

## 小结

> 这个机制的全部智慧在于：**把"协调"从 AI 的脑子里，搬到一个双方都能读的文件里。**
> AI 会忘记对话，但不会忘记文件。
