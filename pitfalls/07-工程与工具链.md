# 07 · 工程与工具链

共 17 条，分五组。**这一篇的问题大多与业务无关**，但排查成本往往比业务 bug 更高——因为它们发生在"你以为一定能用的东西"上。

（大白话：工具链 = 你开发要用的那堆软件：命令行、git、浏览器、Python……它们的坑和业务无关，但排起来更耗时，因为你不会怀疑它们。）

---

## A. Shell 与编码

### A1. 命令执行成功，但没有任何输出

**现象**：Shell 工具返回"成功"，但看不到任何输出。

**为什么危险**：**"命令执行成功但没有输出"和"命令没有执行"是两回事。** 前者会让你误以为一切正常，然后基于错误的前提继续工作——比如以为某个文件已经写入、某个检查已经通过。

**修法**：改用可靠通道。

```
执行（不管输出） → 结果写入 UTF-8 文件 → 用文件读取工具读回来
```

**这个模式虽然笨，但在输出通道不可靠时是唯一可靠的做法。**

### A2. Shell 的部分命令全线失效

**现象**：`ls`、`dirname`、`wc` 等基础命令全部报 `command not found`，但其他命令正常。

**根因**：Shell 的 PATH 环境损坏（某些基础工具的目录不在 PATH 里）。

**修法**：不要在这个 Shell 里排查 PATH——**直接换一个工具**（另一个 shell、或直接调可执行文件的绝对路径、或用脚本语言）。

**教训**：**环境问题要"绕过"而不是"修好"。** 修 PATH 可能花一小时，绕过它花一分钟。

### A3. 写文档时内容被静默修改

**现象**：用 heredoc 写 Markdown 文件，写入的文档里**某些术语消失了**。

具体案例：

```
文中原本有 `wx.getLocation` 这个术语（被反引号包着）
写入后变成了：**背景**： 属需准入开通的隐私接口
                              ↑ 术语位置变成空白
```

**根因**：`<<EOF`（**未加引号**）的 heredoc 会把正文里的反引号当作**命令替换**执行，反引号包起来的内容被当作命令执行后替换成空字符串。

**修法**：

```bash
# ❌ 反引号会被执行
cat <<EOF > file.md

# ✅ 加引号，内容原样写入
cat <<'EOF' > file.md
```

**更好的做法：用文件写入工具直接写文件**，不经过 shell。

**教训**：**静默损坏比报错危险得多。** 这次是靠事后复查才发现术语丢了——如果没复查，文档会带着错误一直传下去。

**推论**：任何"批量写入生成的文档"，写完后**必须抽查**（尤其是特殊字符、术语、代码片段）。

## B. Git 与版本控制

### B1. 全局 URL 重写把凭据发给了第三方

**现象**：推送时凭据被发送到了一个镜像站点。

**根因**：全局 git 配置里有一条 URL 重写规则，把所有官方仓库地址重写为国内镜像地址。**克隆加速用的**，但推送时也生效——凭据跟着一起发过去了。

**修法**：

```bash
# 查看是否存在重写规则
git config --get-regexp 'url\..*\.insteadof'
```

推送时必须绕过。两种方式：

```bash
# 方式一：单次会话使用独立的配置文件
GIT_CONFIG_GLOBAL=/path/to/clean-config git push origin main

# 方式二：使用 SSH 形式（SSH 地址不匹配 https 重写规则）
git remote set-url origin git@host:owner/repo.git
```

**教训**：**为国内网络环境做的"宽松设置"，会连带影响推送安全。** 设置的时候就要意识到它的作用范围不区分"读"和"写"。

### B2. 全局关闭了 TLS 证书校验

**现象**：推送时出现警告：`TLS certificate verification has been disabled`。

**根因**：全局配置里有 `http.sslverify=false`。

**影响面**：所有 https 传输（含推送凭据）暴露于中间人攻击。

**修法**：改为 `true`，或**仅对确需自签证书的主机单独关闭**。

**教训**：**这类"当年为了绕过某个问题而设的开关"，会在之后一直生效，而且没人记得它为什么在那。** 建议定期审一遍全局 git 配置——尤其是 `insteadof` 重写、`sslverify`、`safe.directory` 这几项。

### B3. 写引用文件时的编码坑（值 40 个提交）

**现象**：`git commit` 报错退出且**没有任何输出**；再查日志，发现分支变成"还没有任何提交"，`git status` 突然显示**全部文件都是新增**。

**根因**：手工创建的引用文件**带了 BOM**。git 读不了这个引用 → 认为该分支不存在 → 提交被写成一个**没有父提交的根提交**（丢掉全部历史）→ **引用文件本身也被删掉**。

**修法**：写引用文件一律用 **ASCII 编码**，不要用 UTF-8（会带 BOM）。

**判据（能救命）**：用 `git status` 区分三种"分支没有提交"：

| status 显示 | 含义 | 处理 |
|---|---|---|
| 大量 `A`（全部文件新增） | **没读懂**引用（BOM/损坏） | 修引用文件格式 |
| 大量 `D`（删除） | 引用指向了旧提交 | 检出到正确提交 |
| 若干 `M`（修改） | 工具真的改了文件 | 比对内容 |

**恢复**：从 reflog 里找**父提交正常的那一条**（坏提交的父提交是 40 个零），用它的哈希写回引用文件。

**教训**：**"命令没有输出"是最危险的失败形态。** 报错至少告诉你出事了；静默失败让你以为一切正常。

### B4. 含中文路径时 git 命令解析失败

**现象**：`git -C "含中文的路径"` 报"不是 git 仓库"，即使已经切换到了那个目录。

**修法**：

- 用脚本语言（Python 等）以 `cwd=` 参数指定工作目录；
- 或用 `git --git-dir=<绝对路径>` 这种形式（**它反而没问题**）。

**教训**：**中文路径 + 命令行工具 = 高频踩坑区。** 遇到"文件明明在但工具说不存在"，先怀疑编码，而不是怀疑文件。

### B5. 批量删除时误伤整个目录

**现象**：整理废弃配置时发现**整个工具目录从工作区消失**（41 个文件，含改前备份）。

**为什么没损失**：**这些文件全部已经入库**，用一条 `git restore` 就全部恢复了。

**教训（本篇最值钱的一条）**：

> **这次没翻车，唯一的原因是"所有东西都已经提交"。**
>
> 如果那 41 个文件里有一个未提交的改前备份，它就永久消失了。

**所以批量删除前的三条纪律**：

1. **先确认工作区状态**（`git status` 干净 / 所有改动已提交）；
2. **优先用版本控制恢复**，而不是"小心别删错"；
3. **删除前先看目标列表**，不要用通配符批量删。

## C. 测试与校验

### C1. 测试运行器不接受目录参数

**现象**：`node --test <目录>` 报 `MODULE_NOT_FOUND`。

**修法**：**显式列出测试文件**。

**教训**：这类"本机环境特有的行为"必须写进项目文档——否则每个新会话（包括 AI）都会重新踩一次。

### C2. 测试互相耗尽配额

**现象**：单个测试文件跑得通，多个文件一起跑就失败。

**根因**：限流计数是**模块级**的，而多个测试用例复用同一个用户标识——不隔离就会互相耗尽额度。

**修法**：在每个用例前重置计数（`beforeEach(reset)`）。

**教训**：**模块级状态是测试隔离的敌人。** 任何有状态的模块，测试时都要显式重置。

### C3. 测试需要平台 SDK，本地跑不了

**现象**：某个测试文件在本地跑不通，因为它依赖的模块需要平台 SDK。

**修法（按需选择）**：

| 场景 | 做法 |
|---|---|
| 只需要跑通链路 | **注入 fake SDK**（拦截模块加载，提供最小实现） |
| 需要验证纯逻辑 | **把纯逻辑抽出来单独测试**，不依赖 SDK |
| 必须真实环境 | 只能部署到云端测 |

**项目里的分工**：纯函数验证放独立测试文件；**需要 SDK 的接线验证放在能注入 fake 的那个文件里**（它有 fake SDK，所以能跑）。

**教训**：**"测不了"通常意味着"耦合太紧"。** 把纯逻辑抽出来的过程，本身就是一次解耦。

## D. 渲染与图像工具

### D1. 无头浏览器打印 PDF：profile 被占用导致失败

**现象**：重新生成 PDF 时，命令返回失败、日志文件都没生成。

**根因**：**同一个浏览器 profile 目录被上次的无头进程占用。**

**修法**：**换一个 user-data-dir 重试**。

**教训**：无头浏览器会留下残留进程。**批量/重复渲染时，每次用独立 profile 目录。**

### D2. 无头浏览器返回非零退出码，但成功写出了文件

**现象**：命令返回非零退出码，但目标文件其实是新的。

**修法**：**判断成功要看"文件修改时间是否更新"，不要只看退出码。**

```powershell
# 判断标准：修改时间
(Get-Item $file).LastWriteTime
```

**教训**：**外部工具的成功信号可能不可靠。** 用**产物本身**来判断，比用退出码可靠。

### D3. 截图模式下页面边距不生效（导致误判）

**现象**：截图预览看起来内容贴边、右列像被切掉，以为排版坏了。

**真相**：**截图模式下 `@page` 的边距不生效**（只有打印模式生效）。**PDF 本身是正常的。**

**修法**：**验证 PDF 用页面的实际尺寸（MediaBox），不要靠截图目测。**

**教训（很重要）**：**用错误的工具验证，会得出错误的结论，然后去修一个不存在的问题。** 这类"花时间修一个本来没坏的东西"的浪费，根源都是验证方法错了。

### D4. 中文路径传给渲染工具

**现象**：渲染含中文路径的 HTML 时打不开或输出异常。

**修法**（不同工具各不相同）：

- 用脚本语言把路径转成正确的 URI 形式（自动编码）；
- **或干脆把文件复制到一个纯 ASCII 的临时目录再渲染**（最省事，项目里用的就是这个）。

**教训**：**中文路径问题的"最省事解"通常是"换个路径"，而不是"修好编码"。**

### D5. 隔离环境里没有图像库

**现象**：托管运行时里没有安装图像处理库，但系统运行时里有。

**修法**：按隔离规则建独立虚拟环境安装；或**明确记录"哪个解释器有哪些库"**。

**踩坑细节**：Windows 下虚拟环境的可执行文件在 `Scripts\` 而不是 `bin\`。

**教训**：**在同一台机器上有多个运行时/解释器时，先确认"我正在用哪一个"。** 项目里就有"托管环境无某库、系统环境有"的情况，导致同一个脚本换环境就跑不了。

## E. 设计/排版工具

### E1. 环形图的负偏移不生效

**现象**：用"虚线描边 + 负偏移"画环形图表，四段圆弧**全部从同一个角度起叠**。

**根因**：该渲染引擎不支持负的偏移值。

**修法**：改用**显式圆弧路径**（按角度计算起止点），不依赖偏移技巧。

**教训**：**依赖"偏移量"这类隐式技巧的实现，跨引擎时最容易失效。**

### E2. 填充宽度在横向容器里算错

**现象**：一个横向容器里放一个固定宽度的子项和一个"填充剩余空间"的子项，**填充子项拿到了整个容器的宽度**，把固定宽度的那个顶出去、重叠到下一个容器。

**修法**：**把填充子项改成固定宽度**（由自己算出"容器宽 − 固定宽 − 间距"）。

**教训**：**布局引擎的"自动填充"不总是按你理解的语义工作。** 关键尺寸显式指定，比依赖自动计算可靠。

### E3. 迁移节点后残留旧尺寸

**现象**：把一个元素移动到新的父容器后，它**保留了旧的宽度/填充设置**，在新布局里表现异常（把兄弟元素挤出可视区）。

**修法**：迁移后**复查这些旧尺寸残留**，改成自适应。

**教训**：**结构性改动（移动节点）之后，必须逐个检查被移动节点的尺寸设置。** 布局工具不会帮你清理这些。

### E4. 画布高度被固定时，内容会被裁掉

**现象**：给容器设了固定高度 + 溢出隐藏，**新增内容被挤出可视区域、静默裁掉**。

**修法**：

1. **先出缩略图自查**；
2. 渲染时用**与目标尺寸一致的视口**（CSS 视口即输出尺寸，不加缩放因子）；
3. **量出各区块高度求和核对**，而不是凭感觉。

**教训**：**固定高度的画布 + 溢出隐藏 = 静默丢内容。** 每次改内容后都要量一遍。

**顺带一条排版经验**：当画布高度固定时，"某个区域太高"的请求本质是**重分配**，不是等比缩放——**每缩完一处，必须立刻把等量高度加到用户指定的另一处**，并保持总高仍贴合画布。只缩不加会在底部露白，只加不缩会溢出。

## 一条跨篇的元规律

这一篇的问题有一个共同解法：

> **当工具的行为不可靠时，用产物本身来验证，而不是用工具的报告来验证。**

| 工具报告 | 更可靠的验证 |
|---|---|
| 命令退出码 | **文件修改时间 / 产物内容** |
| 命令"成功" | **把结果写文件再读回来** |
| 截图预览 | **页面的实际尺寸（MediaBox）** |
| 肉眼判断图片 | **用脚本读实际尺寸** |

**根源在于：工具链的"成功"信号，只保证"它跑完了"，不保证"它做对了"。**
