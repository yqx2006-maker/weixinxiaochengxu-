# 04 · 画布与图像处理

共 9 条。这一篇集中在"用 canvas 合成图片"和"处理图片资源"上——**这是最容易出现"代码没报错但结果不对"的领域**。

---

## 1. 复用查询对象，导致画布全白

**现象**：页面上有多个画布，合成出来的图**全是空白的**。

**根因**：代码为了"省事"，把多个画布的 `SelectorQuery` **复用了同一个对象**。而查询对象被复用时，`exec()` 会重新执行——第二次拿到的结果里 `res[0]` 已经没有节点了。

**修法**：**每个画布独立创建查询对象。**

```ts
// ❌ 复用查询对象
const q = wx.createSelectorQuery()
for (const id of canvasIds) q.select('#' + id).fields({ node: true, size: true })
q.exec(...)   // 只有第一个能拿到 node

// ✅ 每个画布一个查询对象
for (const id of canvasIds) {
  wx.createSelectorQuery()
    .select('#' + id)
    .fields({ node: true, size: true })
    .exec((res) => { /* res[0] 就是当前这个画布 */ })
}
```

**必须在代码里写清原因**——否则这段"看起来可以合并"的代码，一定会在某次重构中被"优化"掉，然后画布又全白了。

**教训**：**凡是"看起来多余但必须有"的代码，必须在原地说明原因。**

## 2. 文字的字体没设置，字号继承了残留值

**现象**：某种排版样式的大标题**明显比其他样式的同字号标题小**。

**根因**：`fillText` 之前**从来没有设置过 `ctx.font`**。画布上下文会保留上一次设置的字体，于是字号变成了"上一次用剩的"。

这个 bug 的隐蔽在于：**其他排版样式碰巧都设置了 font，只有这一条路径没设**——所以现象是"只有某一种样式不对"，很容易被当成样式配置问题去排查。

**修法**：`fillText` 前**显式设置 font**：

```ts
ctx.font = `bold ${size}px serif`
```

**教训**：**canvas 是隐式状态机。** 所有影响渲染的状态（font、fillStyle、textAlign、lineWidth…）都必须在**每次绘制前显式设置**，不能依赖"上一步设过了"。

## 3. 图片体积限制卡的是"总体积"，不是单张

**现象**：代码质量扫描报"图片和音频资源超限"。

**根因**：最初的判断是"单张图不能超过某个大小"，于是把所有图都压到阈值以下——**扫描依然失败**。

**真实规则：卡的是所有图片资源的总体积。**

实际过程很能说明问题：原本十几张图共约 195KB，**刚好压线通过**；换成高清版本后涨到约 990KB，立刻失败。修改前的"通过"是**巧合**，不是安全线。

**修法**：两段收敛压缩——先降质量，仍超标再降分辨率。

最终图片总体积降到 164.8KB，分辨率降到 400×267。

**教训**：

1. **"刚好通过"不等于"合规"**，要留余量；
2. **换高清资源前先算总体积**；
3. 如果未来需要更高画质 → 移到云存储/CDN，本地只留必要的图标资源。

## 4. 调色板模式的 PNG 转换会丢色

**现象**：把导出的 PNG 转成 JPG，**底色出现黑块、颜色丢失**。

**根因**：导出的 PNG 是 **`P`（调色板 / 索引色）模式**。直接 `convert("RGB")` 会把索引值当成灰度值处理。

**修法**：三步走

```python
img.convert("RGBA")   # 先展开为带透明通道
   # 压白底（否则透明区域变黑）
   .convert("RGB")    # 再转 RGB
```

**教训**：**图像转换时先看色彩模式。** `P` / `LA` / `CMYK` 这些模式转 `RGB` 都有各自的陷阱，不能无脑转。

## 5. AI 生成的图片带水印

**现象**：AI 生成的封面图右下角有"AI 生成"水印。

**修法**：**缩放前先裁掉底部约 11%**。

**顺序很重要**：必须先裁再缩放（否则水印位置会随缩放变化，裁不准）。

**顺带一个合规提醒**：某些平台要求 AI 生成内容加标识——**去水印前先确认这样做是否符合你所在平台的规则**。这个项目里处理的是内部素材资源，不涉及对外展示。

**教训**：**AI 生成资源进入产品前，要过一道"人眼检查"**——水印、异常肢体、文字乱码，这些自动检测都很难发现。

## 6. 图片写入间歇性失败

**现象**：脚本写图片文件时，间歇性报未知错误。**同一批文件里，有些能写、有些被拦。**

**根因**：文件写入路径经过某层拦截，行为不稳定。

**修法**：**先写到临时文件，再原子替换**：

```
写 xxx.tmp  →  移动到目标路径（覆盖）
```

这个模式的好处是：**失败时不会留下半个损坏的文件**，且绕过了对目标路径的直接写入。

**教训**：**批量文件操作要做成"可重试 + 失败不产生中间态"。** 直接覆盖写是最脆的做法。

## 7. 临时文件路径会失效

**现象**：用户重新打开小程序后，之前的合成图片/照片显示为空白。

**根因**：本地的临时文件路径**不是持久化的**——应用重启后可能失效。

**修法（分场景处理）**：

| 场景 | 处理 |
|---|---|
| 合成的图片 | 用户需要的话就**立即保存到相册**（提示"可保存到相册长期保留"） |
| 界面上的预览 | 图片加载失败时**自动降级为空位**（自愈），不要显示破图 |
| 关键的用户内容 | 存到云存储，用 fileID 换取 |

**教训**：**把"临时路径"当作"可用但随时可能失效"的资源来对待。** 任何长期持有的需求，都必须落盘或上云。

---

## 8. canvas 导出失败不能静默

**现象**：合成失败时，用户看到的是一片空白，**没有任何提示**。

**修法**：失败时在预览区显示"**点此重试**"。

**教训**：**合成类操作必须有可见的失败态。** 因为它不像网络请求那样有天然的失败提示（转圈 → 报错），画布失败时"什么都不发生"和"正在进行中"在视觉上是一样的。

## 9. 竖排文字的几何常量要抽出来

**现象**：一种竖排排版的文字在拖动交互中**命中区域不对**（点不到）。

**根因**：布局用了一组几何常量（位置、半径、宽度），而拖动命中检测**用了另一组硬编码的数值**。两者不同步。

**修法**：把几何常量抽成命名常量（如 `SLIP_CX` / `SLIP_W`），**绘制和命中检测共用同一组值**。

**教训**：**同一份几何信息只能有一个定义处。** 一旦出现第二处，它们就会漂移。

## 一条跨篇的元规律

这一篇的所有问题都有同一个特征：**没有异常，只是结果不对。**

- 画布全白（不是报错）
- 字号偏小（不是报错）
- 颜色丢失（不是报错）
- 水印还在（不是报错）
- 图片空白（不是报错）

**所以图像处理类的工作，不能靠"跑通了"来判断正确性。** 唯一可靠的做法是：

> **每次都真的看一眼输出结果，并且用可量化的方式校验它。**

项目里用过的量化校验手段：
- 用脚本读图片实际尺寸（不靠肉眼判断分辨率对不对）；
- 用独立的图像库**复刻一遍渲染逻辑**，对比生成的预览图（验证排版坐标是否合理）；
- PDF 校验用页面的实际尺寸（MediaBox），**不用截图目测**。

最后这一条有真实教训：

> 用无头浏览器打印 PDF 时，**截图模式下页面边距不生效**（只有打印模式生效），所以截图预览看起来内容贴边、右侧像被切掉。**但 PDF 本身是正常的。**
>
> **教训：验证 PDF 要用页面尺寸，不要靠截图模式判断。** 用错误的工具验证，会得出错误的结论，然后去修一个不存在的问题。
